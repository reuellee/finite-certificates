# Exact semialgebraic certificate method

## What is being preserved

The 9DVL program has produced more than isolated certificate files.  It has
developed a reusable way to turn numerical or combinatorial reconnaissance
into reviewable exact evidence.  This document treats that method and its code
as first-class research outputs while keeping theorem claims separate from
tool claims.

The reusable producer implementation is `exact_semialgebraic/`.  Its analytic
canaries are generated by `build_exact_semialgebraic_toolkit_canaries.py` and
replayed by `verify_exact_semialgebraic_toolkit.py`.  Existing load-bearing
9DVL certificates retain independent verifiers that do not import the
producer implementation.

## Certificate lifecycle

1. **Name the invariant obligation.** State the theorem-level object that is
   missing before choosing a finite reduction.
2. **Bound discovery.** Declare the input universe, exact success and null
   outputs, resource ceiling, and stop rule before running a search.
3. **Replace discovery arithmetic.** Replay the proposed object over integers
   or rationals.  Numerical work may select a candidate but is not evidence.
4. **Emit semantic evidence.** Store source counts, scopes, exact identities,
   normalized polynomial digests, and all unresolved cases—not just a final
   Boolean.
5. **Replay independently.** The verifier reconstructs the quantified source
   universe and proof obligations without importing generator-side decision
   logic at the trust boundary.
6. **Mutate hostile fields.** Corrupt counts, digests, scope labels, and proof
   statuses; require every mutation to be rejected.
7. **Audit scope.** Distinguish a box, a union of box boundaries, a parent
   cell, and the global complex.  Local coverage is never silently promoted.
8. **Publish with runtime isolation.** Give a slow exact replay its own CI job
   and honest allowance.  A process timeout is an infrastructure result, not
   a mathematical failure.
9. **Update the decision ledger.** Advance a theorem score only when every
   invariant promotion condition is closed.

## Reusable exact primitives

The toolkit represents a polynomial as a sparse map from exponent tuples to
rational coefficients.  It currently exposes:

- exact sparse multiplication, evaluation, differentiation, and affine
  pullback in arbitrary parameter dimension;
- primitive integer normalization for stable semantic hashing;
- power-to-tensor-Bernstein conversion on the unit box;
- exact midpoint de Casteljau subdivision in arbitrary dimension;
- power-to-simplex-Bernstein conversion on rational simplices;
- deterministic longest-edge simplex bisection in arbitrary dimension;
- a zero-set classifier with two proof-bearing outcomes:
  `EMPTY_BERNSTEIN` and `NONEMPTY_CORNER`;
- simultaneous-equation exclusion by subdivision; and
- adaptive critical systems using alternative derivative-axis sets.

All budget exhaustion is fail-closed.  `UNRESOLVED` means only that the current
certificate language and budget did not decide the instance.  Likewise, a
false return from simultaneous-equation exclusion is not a common-root claim.

## Component-coverage pattern

For a hypersurface `p=0` in a rational box, feasibility and component coverage
are different obligations.

- If a restriction is affine in some coordinate, an occurring component is
  graph-type (or contains a full fiber), so it cannot be a compact component
  isolated in the box interior.
- Otherwise, a compact interior component would contain extrema of coordinate
  projections.  For a chosen omitted coordinate, such an extremum is a common
  zero of `p` and the derivatives in the other coordinates.
- Proving one such critical system empty excludes compact interior components.
  Trying several derivative-axis sets is valid because each is independently
  sufficient; it is also operationally important when one projection is
  singular or difficult.

This proves that each occurring component meets the boundary of the **declared
box**.  On a box union it reaches the declared union of box boundaries,
including internal seams.  Removing seams or claiming the outer boundary
requires another gluing or missed-component theorem.

## Canaries and falsification

The toolkit certificate includes exact examples that exercise different
logical outcomes:

- a strictly positive 2D quadratic, which must be certified empty;
- a crossing line, which has a rational zero witness;
- an interior circle that requires subdivision before a corner sign witness
  appears;
- a noncompact 3D hyperboloid-like surface whose selected critical system is
  exactly empty; and
- an interior sphere, whose compact component forces the critical-system
  method to refuse an emptiness proof;
- positive and crossing triangle polynomials exercising simplex controls; and
- an interior tetrahedral sphere that forces the simplex classifier to remain
  unresolved rather than confusing budget exhaustion with emptiness.

The sphere is the essential negative canary: accepting it would turn the main
component-coverage argument into a false-proof engine.

## Trust boundaries

The shared toolkit reduces duplicated producer code and makes proof routines
easier to test.  It does not make a producer independent of itself.  A
certificate that depends on these routines must still be checked by a replay
implementation with separately written pullback, Bernstein, subdivision, and
semantic-accounting logic.

Stable semantic digests protect meaning rather than JSON formatting.  They are
domain-separated by certificate type and include normalized polynomials,
statuses, depths, and visited-subbox counts where those values are part of the
published certificate.

## Applicability and limits

The method is useful when degrees are low, coefficients are exact, and
subdivision makes sign or common-zero exclusion sparse.  It can certify
feasibility, local nonoccurrence, and the absence of compact interior
hypersurface components under the critical-point hypotheses above.

It is not a general connected-component roadmap, a cylindrical algebraic
decomposition, or a proof of global gluing.  Singular components, systems that
remain near-zero on many subboxes, and topology across internal seams may need
resultants, exact real-root isolation, stratified roadmaps, or a different
global argument.  Those cases must remain explicit residues.

## Research value independent of 9DVL

The transferable result is the combination of:

- a fail-closed exact API;
- analytic positive and negative canaries;
- semantic, scope-aware certificate records;
- generator/verifier separation;
- adversarial mutation testing; and
- resource-aware CI publication.

That combination is useful beyond this conjecture wherever computer-assisted
research must distinguish discovery, a bounded certificate, and a global
theorem without blurring the boundaries between them.
